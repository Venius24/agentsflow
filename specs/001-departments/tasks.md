- [ ] **T0.4** `agentsflow home init <DIR>`: скелет с отделом `general`, правилами оркестратора, `.gitignore`, `git init` и первым коммитом; не перезаписывает существующее.

## Этап 2. Оркестратор

- [ ] **T2.1** `agentsflow mcp --as <id> --role orchestrator|member`: расширение `mail_mcp.rs`, личные токены по ролям.
- [ ] **T2.2** Инструменты оркестратора: `list_departments`, `list_tasks`, `get_task`, `create_task`, `ask_owner`, `propose_department`, `accept`, `return_task`, `send_to_owner`, `notify_owner`; проверки на стороне шлюза (нет `accept` для `external`, ≤ 1 возврата).
- [ ] **T2.3** `orchestrator.rs`: очередь триггеров со слиянием, один вызов за раз, новая сессия на вызов, промпт из правил + каталога + открытых задач + триггера.
- [ ] **T2.4** Стартовые правила оркестратора в `home init`: как резать сообщение на задачи, когда спрашивать, как ставить риск (сомнение → `external`), как писать хозяину коротко.
- [ ] **T2.5** Telegram: свободный текст хозяина → оркестратору; reply на вопросы → ответ; карточки «новый отдел» (создать / править / в общий) и «приёмка» (принять / вернуть с комментарием).
- [ ] **T2.6** Создание отдела по одобрению: запись директории из черновика, `home check` перед записью, коммит.
- [ ] **T2.7** Инструмент агента `ask_owner`: ход ждёт ответа, задача `waiting`, ответ возвращается агенту.
- [ ] **T2.8** Зависимости из одного сообщения хозяина: оркестратор ставит `depends_on`, результат зависимости уходит во входные данные брифа.
- [ ] **T2.9** Страница: ввод сообщения оркестратору, вопросы и предложения в «Ждёт вас».

Готово, когда (С1, С2, С3, С6): одно сообщение с пятью задачами из Telegram раскладывается по отделам, по расплывчатой приходят уточняющие вопросы одним сообщением, для задачи без отдела — предложение отдела; после ответов все задачи доходят до `done` (internal, принятые оркестратором) или до приёмки хозяином (external).
