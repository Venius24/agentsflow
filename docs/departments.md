# Отделы и оркестратор (`serve --home`)

Режим, в котором вы пишете задачи обычным текстом, а дальше всё идёт само: оркестратор раскладывает сообщение на задачи по отделам, каждый отдел делает работу в свежих сессиях Claude и Codex по своим правилам, внутреннее принимает оркестратор, то, что уходит наружу, принимаете вы. Ответы приходят в Telegram по мере готовности.

Замысел и решения — в [specs/001-departments](../specs/001-departments/spec.md). Установка на сервер — в [vps.md](vps.md).

## Быстрый старт

```sh
agentsflow home init ~/home        # дом: настройки, оркестратор, общий отдел, git
agentsflow home check ~/home       # проверить после правок
agentsflow serve --home ~/home --telegram
```

Telegram настраивается переменными `AGENTSFLOW_TELEGRAM_TOKEN` и `AGENTSFLOW_TELEGRAM_USERS` (см. README, раздел Telegram). Дальше просто пишите боту:

> Сделай пост в канал про запуск Orca, проверь остатки по Байтаку и посмотри, что пишут про рынок AI-агентов.

## Дом

```
home/
  agentsflow.toml          настройки: параллельность, оркестратор, цены Codex, часовой пояс
  orchestrator/AGENTS.md   правила оркестратора
  departments/<id>/
    department.toml        состав, workflow, лимиты, расписания
    AGENTS.md              правила отдела — меняются только с вашего согласия
    memory/notes.md        память отдела — агенты пишут сами
    runs/<task>/           папка запуска: brief.md, result.md, artifacts/
  .agentsflow/             доска, журнал расходов, расписания, лог (не в git)
```

Дом — git-репозиторий: каждое добавленное правило, новый отдел и смена лимита — отдельный коммит, их можно откатить.

## Как идёт задача

1. **Разбор.** Ваше сообщение получает свежая сессия оркестратора. Она отвечает планом: какие задачи, в какие отделы, с каким риском, что спросить. Шлюз проверяет каждое действие и создаёт карточки.
2. **Вопросы.** Если без ответа будет угадывание, задача ждёт: в Telegram приходит карточка с вопросами и кнопкой «✍ Ответить».
3. **Новый отдел.** Если подходящего нет, оркестратор предлагает отдел: «✅ Создать отдел» или «В общий отдел».
4. **Запуск.** Отдел получает бриф (`runs/<task>/brief.md`): правила, выжимку памяти, задачу, ваши ответы, входные данные. Workflow отдела — обычно исполнитель → ревьюер → исправление — идёт до одобрения ревьюера или до предела кругов.
5. **Приёмка.** `internal` (отчёт, анализ, черновик для вас) принимает оркестратор: принять, вернуть один раз с замечанием, или отдать вам. `external` (пост, письмо, изменение в чужой системе) всегда приходит вам: «✅ Принять», «🔁 Ещё круг», «✍ Вернуть с замечанием».
6. **Застряла.** Ревью не пройдено, вышло время, кончился бюджет — задача останавливается и приходит сводка: что сделано, сколько потрачено, кнопки «Ещё круг» и «Закрыть».

## department.toml

```toml
id = "pr"                       # латиница, совпадает с именем папки
title = "Пиар"
description = "Посты, анонсы, тексты для соцсетей"   # по нему оркестратор выбирает отдел
default_risk = "external"       # internal | external; по умолчанию external
max_parallel = 1                # задач отдела одновременно

[limits]
task_usd = 3.0                  # бюджет одной задачи
month_usd = 30.0                # месячный лимит отдела (необязателен)
warn_ratio = 0.8                # предупредить при 80 % месячного лимита
timeout_mins = 60
max_loops = 2                   # кругов ревью

[[agent]]                       # 1–3 агента, хотя бы один doer
id = "writer"
kind = "claude"                 # claude | codex
model = "claude-sonnet-5-5"     # необязательно
roles = ["doer"]

[[agent]]
id = "critic"
kind = "codex"
roles = ["reviewer"]

[[step]]                        # тот же формат шагов, что у workflow
id = "do"
agent = "@doer"
prompt = "{brief}"

[[step]]
id = "review"
agent = "@reviewer"
prompt = "{brief}\n\nРезультат:\n{prev.output}\n\nТы только проверяешь, файлы не меняй. Если всё верно, последней строкой напиши VERDICT: APPROVED."
until = "VERDICT: APPROVED"
otherwise = "fix"
next = "end"

[[step]]
id = "fix"
agent = "@doer"
prompt = "Замечания:\n{review.output}\n\nИсправь и обнови result.md."
next = "review"

[[schedule]]                    # необязательно, сколько угодно
cron = "0 9 * * mon-fri"        # минута час день месяц день-недели
task = "Сводка продаж Байтака за вчера"
title = "Утренняя сводка"
```

Агент Codex, у которого роль только `reviewer`, по умолчанию работает с `sandbox = "read-only"`: с правом записи он кладёт свою рецензию в `result.md` поверх результата исполнителя. Нужна запись — укажите `sandbox = "workspace-write"` явно.

`home check` показывает ошибки всех отделов сразу и предупреждения: нет ревьюера, ревьюер той же модели, что исполнитель, режим bypass.

## Память и правила

- Агент, узнав полезное для следующих задач, дописывает это в `memory.md` в папке запуска. После запуска шлюз переносит запись в `memory/notes.md` с датой и номером задачи; хвост памяти попадает в каждый следующий бриф (`memory_digest_kb`).
- Постоянное правило агент предлагает в `rule.md`. Вам приходит карточка «📜 Добавить / Отклонить». Добавленное правило дописывается в `AGENTS.md` отдельным коммитом; отклонённое запоминается в `memory/rejected.md`, и его больше не предлагают.
- Оркестратор тоже предлагает правила (например, когда вы пишете «запомни: отчёты всегда в xlsx») — отделу или себе.
- `/rules` в боте: открытые предложения и последние правила с кнопкой «↩ Отменить» (`git revert`).

## Заказы между отделами

Если отделу нужен результат другого (пиару — цифры от аналитики), агент описывает заказ в `request.md`. Задача ждёт, оркестратор оформляет заказ задачей другого отдела, а когда она готова, задача-заказчик запускается снова с результатом заказа во входных данных. Ограничения: не больше двух уровней заказов, заказ не идёт в отдел выше по цепочке, бюджет заказа — остаток бюджета заказчика, расход заказа учитывается у заказчика.

## Вопросы отдела

Если без ваших ответов задачу не сделать, агент пишет вопросы в `questions.md`, по одному в строке. Запуск на этом заканчивается без ревью, задача ждёт, вам приходит карточка «✍ Ответить»; после ответа отдел запускается снова с ответами в брифе. С заказом другому отделу так же: после `request.md` ревью не идёт. Ответ «на свой вкус» отдел считает ответом и выбирает сам.

## Изоляция

Запуск отдела работает в своей папке и может читать свой отдел: правила, память, прошлые запуски. Папки других отделов, оркестратора и `.agentsflow` закрыты: такие обращения Claude охрана отклоняет сразу, не спрашивая вас. Результаты задач, от которых зависит запуск (и выполненные заказы), шлюз копирует в `inputs/<задача>/` его папки вместе с `artifacts/`. Codex охрана не видит, ему это сказано в брифе, а ревьюер Codex по умолчанию только читает.

## Расходы

Каждый ход записывается в `.agentsflow/ledger.jsonl` с токенами: Claude сообщает стоимость сам, Codex считается по токенам и ценам `[prices.codex."<модель>"]` в `agentsflow.toml` (без цены в долларах не учитывается, но его токены видны отдельной строкой «без цены»). Карточки задач, отделы на странице и `/spend` показывают доллары и токены: `$0.25 · 340k → 3k токенов` (вход → выход). Задача, превысившая бюджет, останавливается. Отдел, исчерпавший `month_usd`, останавливает запуски и держит очередь; при `warn_ratio` приходит предупреждение. `/spend` в боте показывает расходы за месяц и поднимает лимит на 50 %.

## Расписания

`[[schedule]]` в отделе ставит задачу в очередь по cron из пяти полей (`*`, списки, диапазоны, шаги `*/15`, имена `mon`/`jan`, `@daily`, `@weekly`, `@monthly`). Время — по `utc_offset` в `agentsflow.toml` (например `"+05:00"`). После перезапуска сервера срабатывание не повторяется, а пропущенное за время простоя выполняется один раз. `/schedules`: пауза, «⚡ Сейчас».

## HTTP API (режим `--home`)

| Метод и путь | Что делает |
|---|---|
| `GET /api/departments` | отделы, агенты, лимиты, расход за месяц |
| `POST /api/orchestrator` `{text}` | сообщение оркестратору |
| `POST /api/work` `{text, department, title?, risk?, depends_on?, budget_usd?}` | задача в отдел напрямую |
| `POST /api/tasks/{id}/answer` `{text}` | ответ на вопросы |
| `POST /api/tasks/{id}/proposal` `{create}` | решение по новому отделу |
| `POST /api/tasks/{id}/return` `{text}` | вернуть с замечанием |
| `POST /api/tasks/{id}/stop`, `/retry` | остановить, поставить снова |
| `GET /api/tasks/{id}/result` | текст result.md |
| `GET /api/rules`, `POST /api/rules/{target}/{id}/approve\|reject`, `POST /api/rules/revert/{commit}` | правила |
| `GET /api/schedules`, `POST /api/schedules/{key}/pause\|resume\|run` | расписания |
| `GET /api/runs`, `GET /api/spend`, `POST /api/home/reload` | запуски, расходы, перечитать дом |

## Что стоит знать

- Свежая сессия Claude — это около 95 тысяч токенов контекста на старте; разбор сообщения оркестратором на Sonnet стоит порядка $0.08, короткая задача отдела — $0.2–0.4.
- Codex на подписке не сообщает стоимость: без `[prices.codex]` его расход не попадает в лимиты.
- Месяц в журнале расходов считается по UTC.
- Страница в этом режиме открывается на вкладке «Отделы»: сообщение оркестратору, «Ждёт вас» (вопросы, новые отделы, приёмка, застрявшие, правила), идущие задачи, отделы с расходом, расписания и последние правила. Запуски отделов не заводят отдельных чатов на странице.
